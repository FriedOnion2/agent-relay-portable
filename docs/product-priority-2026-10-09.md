# 下一步优先级：使用体验与差异化功能

评估日期：2026-10-09（Australia/Brisbane）。交付基线：`ab6a2ae`。本轮只增加研究文档，不实施产品改动。详细 GitHub 核查见 [竞品笔记](research-competitors-2026-10-09.md)。

## 建议

**先用一个有边界的迭代优化现有任务流程，再做“可携带证据的 Skill 生命周期”。**这里的 UI 优化重点是让用户找到会话、选对迁移方式、处理冲突、确认恢复结果；换配色和图标的收益排在后面。兼容性与真实续聊验证应贯穿这两步。

现在再同时铺开 Profile、云同步、常驻守护或更多客户端，会扩大维护面；其中多数已有直接竞品。已有功能已经足以支撑一次完整的产品体验升级。推荐组合定位：**国产与海外客户端的统一跨系统搬迁，加上无需模型 API 的历史证据发现和可追溯 Skill 资产管理**。这是候选定位，不能宣称市场唯一。

这个建议基于公开资料和当前界面走查，尚无用户任务完成率或留存数据。若用户实际最常失败的是格式恢复，应先修兼容；若多数用户每周双端接力，应把冲突检测与增量提前。竞品星数不能替代这些证据。

## 当前已有功能，避免重复开发

当前 README、[搜索与提炼文档](search-and-skills.md) 和源码已有：本地全文搜索、确定性 Skill 草稿及证据、adapter 插件与格式自检、迁移保真度预览、中英文、批量迁移、敏感信息脱敏、操作记录/撤销、会话 diff、会话/完整 Skill ZIP 存储，以及 Windows↔Ubuntu 原生路径迁移。

六个读取入口不等于六个可写目标：通用写入目前是 WorkBuddy、DSH、Claude、Codex。Claude SDK 默认日志与 Claude Code 共享，不能仅靠 transcript 判定创建者。不能向用户暗示复制记录就克隆了 SDK runtime、账号、权限或所有客户端 UI 状态。

搜索已有增量指纹更新；它与跨设备会话增量同步不是同一功能。Skill 当前已有完整目录打包，但尚无完整目录版本历史、跨设备分歧处理及与草稿证据绑定的生命周期。

## 当前界面走查：优先改流程

用独立合成目录启动当前 Web UI，六个 Agent 根、数据、索引和日志全部指向隔离目录；生成三条 WorkBuddy 演示会话。走查首页、详情、对话存储、搜索首次索引与检索。未对真实会话、Skill 或配置进行读写，也未执行历史命令。这不是 Windows/macOS/Linux 完整可用性测试。

观察与源码依据为 [当前 index.html](https://github.com/FriedOnion2/agent-relay-portable/blob/ab6a2ae/app/web/index.html)：

| 可核查的现状 | 用户需要自己理解的内容 | 建议验收方向 |
|---|---|---|
| 顶部五个业务面板，加六个来源 tabs；首页先展示目标、路径、工具与思考选项 | 本机转换、双系统导入、另一台设备 ZIP 恢复走哪条路 | 先选任务：“本机换 Agent / 搬到另一台设备 / 找历史 / 管 Skill”；当前任务突出一个主操作 |
| 对话存储面板说明让用户到背后的左侧列表勾选；已有包的“选择恢复”可填包路径 | 从保存到拷贝到恢复的前后关系；新包在默认库外时怎样选择 | 保存与恢复分步；库内点选包，库外提供受限文件/目录选择；说明选择的是服务所在设备的文件 |
| 恢复字段需要项目目录，可选手填新 UUID；后端已有冲突拒绝与保真预览 | Windows 路径怎样对应 Ubuntu/macOS；同 ID 冲突怎样解决 | 项目映射先校验，再预览；冲突界面给“跳过 / 生成新 ID”可解释选择，保留不覆盖边界 |
| 搜索、索引设置、提炼、候选、草稿编辑在一个覆盖面板内；标题搜索是另一入口 | 标题搜索和全文搜索差别；索引是否新鲜；为何没有候选 | 独立搜索页面或明确分区；首用引导建索引、显示更新时间；无候选解释条件，进阶筛选折叠 |
| 全文结果已有“打开本机原会话”；离线缓存有来源标记；草稿导出需人工审核 | 离线缓存为什么不能直接迁移；导出草稿怎样进入 Skill 存储 | 保留现有跳转；离线记录明确给可做操作；审核导出后连接到 Skill 资产流程，安装仍需显式动作 |
| 通用迁移成功反馈主要是短暂 toast + 复制路径；原生导入与 ZIP 恢复已有持久结果/部分续聊命令 | 成功写文件后，究竟到哪查看、是否真的已续聊验证 | 统一持久结果卡：来源/目标/项目/新 ID/警告/续聊命令/操作记录；“已写入”和“客户端已验证”分开 |
| 大面板通过 display 显隐，迁移确认已有原生 dialog | 面板之间的焦点、返回、键盘导航如何工作 | 主任务用路由/页面或正确 dialog；明确返回位置、焦点恢复、Esc 行为，中英文窄桌面窗口检查 |

这些是体验改善机会，不是宣称已复现数据损坏。后台任务已有进度与取消，撤销已有修改后保留机制；优化应复用并呈现这些能力。无需为本轮 UI 换框架，也无需重写 adapter。

复核远端时 #40 已合并，目录快照不完整的撤销保护已进入 main；[#42 macOS 签名 PR](https://github.com/FriedOnion2/agent-relay-portable/pull/42)仍未合并。应继续保留兼容/发布验证，避免把界面打磨当作可靠性替代。

## 可确认的下一轮范围

建议按小 PR 交付，协作者可并行评审，先不做整体重写：

1. **导航与首用引导**：任务入口、来源/可写能力、目录缺失与索引状态、主操作层级。
2. **迁移/恢复向导**：来源与包选择 → 项目映射与冲突 → 保真度预览 → 执行 → 持久结果；复用已有 dry-run/token 校验与操作记录。
3. **搜索与 Skill 衔接**：搜索与提炼清晰分区、候选证据、审核导出、导出后存储入口；完整目录版本仍留在后续功能 PR。

验收任务先覆盖：首次启动且一个客户端目录缺失；Windows 会话包恢复到 Ubuntu/macOS 项目；同 ID 冲突；查到本机或离线历史；查看三会话证据并审核导出。三系统使用合成数据验证读写安全；中文/英文、键盘导航和窄桌面窗口验证交互。CLI、插件与原生格式逻辑保持独立可测。

记录首次任务完成时间、错误/折返次数、是否需要解释及能否定位目标记录；建议邀请 3–5 名实际用户或协作者走查，不把小样本当市场统计。若主要失败仍在格式/续聊，下一轮资源应转向兼容；若流程已经顺畅且频繁重复导出，增量/冲突再提前。

下一项 Skill MVP 验收：同一个完整目录两次修改产生不同不可变版本；一台 Windows 与一台 Ubuntu/macOS 离线交换后，能看到 SKILL.md/脚本/资源差异及草稿证据；冲突保留两边；恢复可核对树 hash 与记录；从不自动执行 Skill 脚本。证据只按用户选择携带，避免默认为每个 Skill 捆绑完整敏感会话。

实施前仍按用户此前要求确认方向。本轮研究文档 PR 可供协作者核查事实与优先级，不代表新功能已开工。
