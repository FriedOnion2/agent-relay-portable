## Standards

独立规范审查发现三项，均以合成数据复现并修复：

1. **P2：标题按中文内容猜翻译 key。** 违反 [i18n 维护规则](../dev/i18n.md)。删除 `PLACEHOLDER_TITLES` / `displayTitle()`；来源只给真正生成的占位标题附 `Message`，前端复用 `tm(row, 'title')`。新索引保留可选元数据，旧纯文本标题不误判。
2. **P2：英文 CLI 生成中文 Skill 草稿。** `extract-skills` 漏传语言，已传递当前 CLI 语言，回归断言实际候选正文与说明。
3. **P3：英文 doctor 读取错误仍中文。** 用现有递归消息渲染器显示错误；普通外部异常详情保持原文。

前端拆文件和文档分组有明确维护价值，保留。精简集中在移除猜测字典、复用递归消息格式化与 argparse 参数处理，不削减迁移或存储能力。

## Spec

独立需求审查依据原 PR 说明发现五项，均已修复：

1. **P2：自定义标题误译或阻断列表。** PR #58 要求用户标题原样显示；同名标题被翻译，`constructor` / `toString` / `__proto__` 还会命中对象原型属性。改用显式消息元数据，并测试这些真实标题的列表显示。
2. **P2：英文 Markdown 来源注释仍中文。** PR #58 要求生成文本随语言变化；嵌套 `Message` 参数绕过翻译。`lang_text()` 复用递归渲染，测试元宝和 Claude 的生成说明，保留用户备注与正文。
3. **P2：未知语言未回退中文。** PR #59 与 CLI 文档约定未知值回退；原 argparse choices 却拒绝该值。改用同一规范化函数，重复 `--lang` 按 argparse 取最后值，未知环境值不再截断成合法语言。
4. **P2：语言改变固有 JSON 字段。** PR #59 承诺 JSON 数据稳定；插件列表提示随语言变化。恢复稳定提示，测试两种语言返回相同 JSON。
5. **P2：Skill 命令参考缺必填来源。** 中英文 `skills` / `store-skills` 语法已补齐来源参数。

两轴初审分别发现 3 项和 5 项；各轴最严重问题均为标题处理。所有列出的发现已有修复及回归验证。另修复文档目录链接，站点严格构建无警告或未识别链接。
