# 国际化维护

词条只存在于 `app/web/locales.zh.json` 和 `app/web/locales.en.json`，由本机 HTTP 服务加载，无需外网或新增依赖。key 使用 `ui.`、`msg.`、`err.` 前缀与稳定英文语义名称；修改文案时保留 key。两种语言的 key 和 `{name}` 占位符必须一致。

## 前端

动态文案用 `tr('ui.n_selected', {n: count})`。静态节点使用 `data-i18n="ui.home"`；属性使用 `data-i18n-placeholder`、`data-i18n-title` 或 `data-i18n-aria-label`。含输入框或其他子节点的标签只给文字节点外的 span 绑定，避免切换语言时覆盖控件。

服务端标量优先用 `tm(row, 'error')`，列表用 `tms(row, 'warnings')`。它们分别读取 `error_message` 和 `warnings_messages`，仍可接收旧文本。`ts(descriptor)` 递归翻译嵌套参数；普通字符串、未知 code 的 fallback 和外部异常详情原样显示。不要从正文猜翻译 key，不要增加按中文句式匹配的正则。

## Python 与 HTTP 兼容

```python
from .messages import text, error_text

raise ValueError(text('err.source_unreadable', detail=text('msg.session_unreadable')))
# 捕获异常时用 error_text(exc)，不要用 str(exc) 丢掉消息描述。
```

`Message` 是字符串子类，CLI 输出及旧文本字段保持原文；异常类型不变。HTTP 在原字段旁新增描述，例如：

```json
{
  "error": "源会话不可读：会话无法读取",
  "error_message": {
    "code": "err.source_unreadable",
    "params": {"detail": {"code": "msg.session_unreadable", "params": {}, "fallback": "会话无法读取"}},
    "fallback": "源会话不可读：会话无法读取"
  }
}
```

多条消息拼接用 `join_text` 保留嵌套描述。操作日志写入时保存新增字段，旧日志仍可读。未知系统/第三方异常用 `err.external` 包装详情，不伪造业务 code。会话正文、Skill 文件内容、工具参数与文件路径保持数据语义，不国际化。

## 检查与分发

运行 `python -m unittest discover -s tests` 和 `node --test tests/web.test.cjs`。检查涵盖 Python 调用的 code 和命名参数、静态绑定、缺失 key、占位符漂移、中文文案变更、API 状态码、后台任务和操作日志。前端直接调用不存在的 key 会报错；未知外部描述会使用 fallback。

wheel 的 `relay_web` package-data 包含 JSON；冻结包复制完整 web 目录。`scripts/smoke_release.py` 在真实打包服务上加载两份词条和 i18n.js，用打包服务的真实错误执行中英文翻译验证。PR 的 Portable package validation 检查 Windows x64、Ubuntu 22.04 x64、Mac arm64 / x64，验证过程不发布版本。
